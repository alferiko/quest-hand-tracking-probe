# Quest Hand Tracking Probe

Самостоятельное OpenXR-демо отслеживания пальцев камерами Quest, когда в той же
руке находится работающий контроллер. Проверено на Quest 3. Поддержка других
гарнитур и версий системного ПО не проверена.

[English documentation](README.md) · [Скачать APK](https://github.com/alferiko/quest-hand-tracking-probe/releases/latest)

## Как проверить

1. Включите режим разработчика и USB-отладку для установки APK, а также
   отслеживание рук в настройках гарнитуры.
2. Установите APK из Releases:
   ```powershell
   adb install -r quest-hand-tracking-probe-v0.1.0.apk
   adb shell am start -n io.github.alferiko.handprobe/android.app.NativeActivity
   ```
   В неизвестных источниках приложение называется **Quest Hand Probe**.
3. Убедитесь, что панель показывает `FOCUS YES`, `SOURCE API YES`, `MULTIMODAL ON`.
4. Положите контроллеры, покажите открытые ладони примерно на 10 секунд.
5. Возьмите один контроллер и двигайте пальцами этой руки. Нажмите и отпустите
   курок и грип. Повторите с другой рукой, затем с двумя контроллерами.
   Используйте ремешки.
6. Смотрите на строку **CAMERA ONLY**: зелёный скелет должен следовать пальцам.
7. Снова положите контроллеры и проверьте восстановление отслеживания.

Для каждой руки создаются два трекера: **AUTO** разрешает камерный и контроллерный
источники, **CAMERA ONLY** запрашивает только камерный. AUTO может выбрать
контроллерную позу, даже когда отдельный CAMERA ONLY получает камерные суставы.

- Зелёный `CAMERA`: runtime сообщает активный камерный источник.
- Оранжевый `CONTROLLER`: поза рассчитана по данным контроллера.
- `UNKNOWN SOURCE`, `INACTIVE`, `UNAVAILABLE`, `ERROR`: источник не подтверждён
  или данные недоступны; такие состояния не считаются камерным отслеживанием.
- `VALID` / `TRACKED`: число суставов с соответствующими флагами позиции.
- `CTRL ON`, `TRIG`, `GRIP`: активность обычного контроллерного ввода.

Панель рисует схематическую проекцию на плоскость ладони с привязкой к запястью.
Это не наложение рук в мировом пространстве. Исходные 3D-позиции, ориентации и
флаги в пространстве LOCAL записываются в CSV.

Активный контроллерный action сам по себе не доказывает, что контроллер держат
в руке. Камерный источник также может восстанавливать закрытые суставы. Для
проверки нужны наблюдение в шлеме и движения отдельных пальцев; это демо
доступности данных, а не измерение точности каждого сустава.

## Сборка

Нужны Windows, PowerShell 7, JDK 17, Android SDK platform 35, Build Tools 35.0.0
и NDK 27.0.12077973. Укажите `ANDROID_HOME` и `JAVA_HOME` либо пути параметрами:

```powershell
./build.ps1 -Sdk 'C:\Android\Sdk' -Jdk 'C:\Java\jdk-17'
```

Скрипт скачает официальный OpenXR 1.1.53 из Maven Central, проверит SHA256 и
соберёт `dist/quest-hand-tracking-probe-v0.1.0.apk`. Для следующих сборок можно
использовать сохранённую зависимость без сети. Ключ подписи создаётся локально
в `.local/` и не попадает в Git. Для перехода с опубликованного APK на свою
сборку нужно предварительно удалить установленное приложение; перед удалением
экспортируйте нужные журналы.

## Журналы

Данные сохраняются только на устройстве, отдельно для каждого запуска.
Изображения камер не собираются, телеметрия не отправляется. CSV ограничен
18 000 группами измерений при частоте до 10 Гц; после лимита панель продолжает
работать. Для анализа нужен Python 3.

```powershell
./collect.ps1
python summarize.py captures/<каталог>/device-files/probe-<время>.csv --out summary.json
python -m unittest discover -s tests -v
```

При нескольких устройствах передайте `-Serial`; для ADB вне PATH — `-Adb`.
Экспорт не удаляет журналы со шлема. Анализатор пропускает неполные группы,
считает источники поз, совпадения камерных данных с контроллерным вводом и
диапазоны сгибания пальцев. Совпадения требуют сопоставления с наблюдениями
пользователя; сами по себе они не подтверждают точность отслеживания.
